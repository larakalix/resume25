## Dependency flow

`Vue pages → Nuxt query adapters → HTTP routes → application queries → repository ports ← mock infrastructure`

- `src/domain/content/models.ts`: published Profile, Project, ArticleSummary, Article, Experience, Resume, and page DTO types. No Vue, Nuxt, SDK, or validation-library imports.
- `src/domain/content/repositories.ts`: narrow profile, project, article, and resume repository contracts.
- `src/application/content/portfolio-queries.ts`: selection, newest-first writing, neighboring articles, and home aggregation. Receives interfaces; no network or framework calls. A missing article returns null; upstream failures propagate, not empty successful collections.
- `src/infrastructure/content/mock-repositories.ts`: validated existing local data, detached copies, and metadata-only listing mapping. Article markup is trusted locally authored HTML; a real CMS adapter must sanitize/allowlist external HTML or map trusted rich text before returning Article.content.
- `src/server/utils/portfolio.ts`: the composition root and source replacement point. Only server code imports the concrete repositories.
- `src/server/api/portfolio/`: public read-only endpoints for home, projects, articles/list, articles/:slug, profile, and resume. Unknown articles return 404.
- `src/composables/use-portfolio-query.ts` and `use-post.ts`: Nuxt HTTP adapters. Stable keys and SSR payload hydration prevent duplicate initial browser fetches. Pages receive pending/error/data/refresh state and render recovery controls. JSON decoding is explicit for static-host compatibility.

Site navigation and SEO templates remain application configuration in `src/config`; they are not remote CMS credentials or repository dependencies. The existing Contentful schemas, export format, IDs, and export script are retained. Lemonade schema templates and migration seed files are also prepared offline under `cms/lemonade/`; they do not connect or replace the running repositories. Their symbolic migration identities require resolution to destination entry UUIDs before a future entry migration; media paths remain ordinary source paths, not uploaded media IDs. Domain types are re-exported from legacy type paths to preserve callers while removing schema-library dependencies from the domain.

## SOLID in practice

Narrow repository interfaces avoid forcing article logic onto profile consumers. Dependency direction points inward; the composition root owns concrete construction. No abstract base classes or container framework are needed.
